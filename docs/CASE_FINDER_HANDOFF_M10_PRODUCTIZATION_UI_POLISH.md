# CASE_FINDER_HANDOFF_M10_PRODUCTIZATION_UI_POLISH

## 1. 목적

M9/M9RR 계열에서 확정된 검색 configuration과 M9RR3 managed runtime을 변경하지 않고, Case Finder를 개발용 검색 골격에서 실제 사용 가능한 로컬 제품 UI로 마감한다.

M10의 목표는 검색 정확도 개선이 아니다.

```text
M9 / M9RR
= 검색 configuration 확정

M9RR3
= managed runtime 확정

M10
= 사용자 UI / 상태 표현 / 설정 UX / 제품 통합 마감

M11+
= Windows Installer / Clean-PC Validation
```

이번 단계가 끝나기 전에는 installer 제작을 시작하지 않는다.

## 2. 시작 조건

M10 작업 시작 전 M9RR3를 다음 상태로 동결한다.

```text
M9RR3_MANAGED_RUNTIME_PASS
```

확인된 운영 기준:

```text
Managed Codex: stable 0.147.0 pinned

Golden:
임차보증금을 돌려받지 못했을 때

Result:
HTTP 200
stage=LUNA_NATIVE
verified items=4
last success state=MODEL_FINAL

restricted MCP:
9 calls total
- search: 4
- detail: 5

elapsed:
25,895 ms

auth: PASS
restricted MCP: PASS
EvidenceLedger / FinalSelectionGate: PASS
protocol: PASS
```

이전 `0.147.0-alpha.6.5` timeout은 stable `0.147.0`에서 재현되지 않았으며 managed-runtime compatibility 문제로 종결한다.

다음 항목은 이 해결 과정에서 변경하지 않았다.

```text
검색 알고리즘
Luna prompt
tool surface
EvidenceLedger
FinalSelectionGate
```

### 필수 선행 마감

M10 구현 전에 M9RR3 변경사항을:

```text
1. runtime-manifest에 Codex 0.147.0 pin
2. M9RR3 report를 PASS로 갱신
3. npm run verify
4. git diff --check
5. commit
```

하고 그 commit SHA를 M10 Base SHA로 기록한다.

아직 commit되지 않았다면 SHA를 추정하거나 문서에 가짜 값을 넣지 않는다.

## 3. Canonical product specification

M10 UI는 다음 문서를 제품 요구사항의 canonical source로 사용한다.

```text
docs/CASE_FINDER_PRODUCT_SPEC_V2.md
```

해당 문서와 이 Handoff가 충돌하면:

```text
1. 검색 정확성 / safety contract
   → PRODUCT_SPEC_V2 우선

2. M10 구현 범위 / 순서 / stop-loss
   → 본 Handoff 우선
```

## 4. 현재 UI 기준

현재 제품 화면은 `public/index.html` 중심의 최소 골격이다.

현재 구성:

```text
Fable 판례 검색기
간단한 설명
검색 input
검색 button
result div
footer
```

현재 client script는:

```text
POST /ask
→ JSON 수신
→ payload.html을 #result에 삽입
```

하는 수준이다.

M10에서는 이 골격을 제품 UI로 발전시키되, 프론트엔드 framework를 새로 도입하지 않는다.

## 5. M10 절대 조건

### 5.1 검색 configuration 동결

M10에서 다음 변경 금지:

```text
Gemini D prompt
Gemini D ranking
Gemini D query generation
Gemini D selector

candidateMax
resultMax

Luna prompt
Luna search policy
Luna tool surface
Luna reasoning effort

EvidenceLedger
FinalSelectionGate

새 model benchmark
새 blind set
A6 재튜닝
```

UI 때문에 검색 결과가 달라져서는 안 된다.

### 5.2 사용자 표시 데이터의 provenance 유지

다음은 기존 provider/validator contract를 그대로 따른다.

```text
사건번호
사건명
법원
선고일
판시사항
판결요지 / 결정요지
법령 조문
공식 링크
```

UI가 표시 편의를 위해 내용을 생성·보완·추정하지 않는다.

### 5.3 Silent fallback 금지

```text
Luna 실패
→ Gemini 자동 전환 금지
```

사용자에게 현재 상태를 정확히 알리고 직접 다른 검색 엔진을 선택하게 한다.

### 5.4 private reasoning 노출 금지

Progress, status, admin, error UI 어디에도 다음을 표시하지 않는다.

```text
chain-of-thought
system prompt
raw tool planning
raw search query generated by model
tool arguments
auth token
secret
internal prompt
```

## 7. M10-A — 메인 검색 화면 Polish

첫 화면에서 사용자가 다음을 즉시 이해해야 한다.

```text
1. 무엇을 검색하는 도구인지
2. 현재 어떤 검색 엔진을 사용하는지
3. 질문을 어디에 입력하는지
4. 검색이 진행 중인지
5. 결과가 성공/없음/실패 중 어떤 상태인지
```

메인 화면 최소 구성:

```text
[Case Finder]

판례·법령 검색 도구 안내

[검색 엔진 상태 / selector]

[질문 입력]
[검색]

[검색 진행 상태]

[결과]

[출처 / 면책]
```

검색 input은 사건번호와 자연어 질문을 모두 받는다.

권장 placeholder:

```text
사건번호 또는 법률 질문을 입력하세요
예: 임차보증금을 돌려받지 못했을 때
```

예시 문구를 실제 입력값으로 자동 제출하지 않는다.

## 8. 검색 엔진 UI

제품에 노출할 선택지는 정확히 두 개다.

```text
Gemini 빠른 검색
→ gemini_d

Luna 고정밀 검색
→ luna_native
```

노출 금지:

```text
Gemini A6
Gemini AO-v2
legacy/internal adapter
```

현재 runtime configuration과 selector 동작 방식을 명확히 한다.

설정 변경이 서버 재시작을 요구하는 기존 구조라면 메인 화면에서 selector를 즉시 변경 가능한 것처럼 오해하게 만들지 않는다.

최소 구현:

```text
현재 엔진 표시
+
[설정 변경] → /admin
```

backend가 안전한 runtime switching을 이미 지원하는 경우에만 직접 selector를 사용한다.

M10을 위해 검색 runtime switching 구조를 새로 설계하지 않는다.

## 9. M10-B — 결과 UI

최종 결과는 아래 순서를 기본으로 한다.

```text
[사용자 질문]

[검색 안내 / intro]

[관련 판례]

[관련 법규]

[출처 / 면책]
```

### 판례 카드

adapter final result의 모든 verified item을 표시한다.

각 카드 최소:

```text
관련성 label

사건번호 + 공식 원문 링크
사건명
법원
선고일

판시사항

판결요지 또는 결정요지
```

기존 contract의:

```text
direct
related
```

를 사용자 친화적 표현으로 표시할 수 있다.

예:

```text
직접 관련
관련 판례
```

내부 값 자체는 변경하지 않는다.

renderer-level 임의 제한으로 verified 하위 판례의 판시사항·판결요지·결정요지를 숨기지 않는다.

"모두 표시"는 adapter final result에 포함되고 detail verification이 성공한 item 전부를 의미하며, raw candidate 전체를 새로 상세조회하는 의미가 아니다.

## 10. M10-C — 관련 법규 UI

관련 법규는 기본 접힘으로 표시한다.

권장:

```html
<details>
```

예:

```text
민법 제XXX조
조문 제목

[전문 보기 ▾]
```

확장 시 provider에서 취득한 조문 전문을 표시한다.

조문 제목은 provider evidence가 있을 때만 표시한다.

공식 법령 링크는 유지한다.

법령 전문을 browser/client가 별도로 생성하거나 수정하지 않는다.

## 11. M10-D — Terminal state UX

backend의 terminal semantics를 UI에 명확히 반영한다.

최소 구분:

```text
SUCCESS
NO_RESULT
SEARCH_FAILED
SAFETY_REJECTED
LUNA_RUNTIME_UNAVAILABLE
NETWORK / SERVER ERROR
```

각 상태를 같은 "검색 실패" 한 문장으로 뭉개지 않는다.

### NO_RESULT

정상 검색 완료지만 표시 가능한 결과가 없는 상태다. 시스템 오류처럼 표현하지 않는다.

### SEARCH_FAILED

후보는 있었지만 상세 원문 검증 등을 통과하지 못한 경우다. `NO_RESULT`와 구분하고 기존 shared product message contract를 유지한다.

### SAFETY_REJECTED

검증 안전장치에 의해 결과 표시가 차단된 경우다. 내부 gate나 reasoning 상세를 노출하지 않는다.

### LUNA_RUNTIME_UNAVAILABLE

Luna 선택 상태에서 runtime 문제가 발생하면 명확한 안내를 제공한다.

Gemini로 자동 재시도하지 않는다.

## 12. M10-E — 직접 사건번호 조회 실패 UX

직접 사건번호 조회 실패 시 일반 자연어 `NO_RESULT`와 구분한다.

Primary:

```text
해당 사건번호의 판결을 국가법령정보센터에서 찾지 못했습니다.
사건번호가 정확한지 다시 확인해 주세요.
```

Secondary:

```text
국가법령정보센터에 수록되지 않았거나 공개 범위가 다른 판결은
대한민국 법원의 판결서 인터넷열람 또는 판결서사본 제공신청에서
확인할 수 있는 경우가 있습니다.
```

"해당 범위면 반드시 찾을 수 있다"는 표현은 금지한다.

## 13. M10-F — Loading / Progress UX

확정 threshold:

```text
LOADING_UI_THRESHOLD_MS = 1000
```

1초 이내 완료되는 검색에서는 상세 progress panel을 표시하지 않는다.

시간 경과만으로 가짜 progress를 만들지 않는다.

권장 event contract:

```text
SEARCH_STARTED
ROUTE_IDENTIFIED
ANALYSIS_COMPLETE
LAW_EVIDENCE_UPDATED
CANDIDATES_FOUND
DETAIL_VERIFIED
FINALIZING
SEARCH_COMPLETE
SEARCH_FAILED
```

UI에 표시 가능한 정보:

```text
현재 단계
후보 수
검증된 판례 수
확인된 관련 법령 수
```

금지:

```text
LLM reasoning
tool args
raw model search plans
prompt
```

Progress는 ETA가 아니다.

권장 표현:

```text
관련 판례를 찾고 있습니다.

✓ 질문 확인
✓ 관련 법령 확인
✓ 판례 후보 검색
● 판례 원문 검증 · 4건 확인
○ 결과 정리
```

percentage를 표시하려면 host가 정의한 monotonic stage indicator여야 한다. 단순 elapsed-time percentage는 금지한다.

## 14. M10-G — Streaming

기존:

```text
POST /ask
```

JSON endpoint는 유지한다.

제품 UI용으로 권장:

```text
POST /ask/stream
Content-Type: text/event-stream
```

Browser는 `fetch()` response body stream을 읽는다.

별도 DB, job queue, WebSocket, search-task server를 만들지 않는다.

final event는 기존 canonical result를 그대로 전달해야 하며 validator/renderer contract를 우회하지 않는다.

기존 `POST /ask` backward compatibility를 유지한다.

## 15. M10-H — Status UI

메인 화면에 간단한 상태 영역을 둔다.

예:

```text
검색 엔진      Luna 고정밀 검색
법령 API       연결됨
Gemini 사용량  로컬 추정
Luna 사용량    확인 가능 / 확인 불가
```

상세 secret/env는 표시하지 않는다.

기존 `/health` 및 M9RR3 Luna readiness 정보를 재사용한다.

UI 때문에 실제 LLM query를 추가 실행하지 않는다.

상태 조회 실패가 검색 기능 자체를 막아서는 안 된다.

## 16. M10-I — Quota UX

Quota는 UX 정보이며 검색 정확성이나 validator와 결합하지 않는다.

Quota 조회 실패는 검색 가능 여부와 분리한다.

### Luna quota

가능한 경우 structured rate-limit 정보를 사용한다.

표현 예:

```text
Luna 64% 남음 · 17:42 초기화
```

실제 window 정보를 사용하고 "5시간", "주간"을 임의 hard-code하지 않는다.

정보를 읽지 못하면:

```text
Luna 사용량 확인 불가
```

로 degrade한다.

### Gemini quota

공식 usage/limit source가 있으면 사용한다.

기존 local counter를 사용할 경우 반드시:

```text
로컬 추정
```

이라고 표시한다.

다른 앱의 동일 project 사용량이 포함되지 않을 수 있음을 숨기지 않는다.

Quota 구현을 위해 M10 범위를 과도하게 확장하지 않는다. provider 접근이 구조적으로 어렵다면 graceful degradation을 PASS로 인정한다.

## 17. M10-J — `/admin`

로컬 전용 설정 화면을 제공한다.

```text
/admin
```

raw `.env` editor는 만들지 않는다.

whitelist 설정만 노출한다.

### 제품 사용자용 최소 설정

```text
SEARCH_ADAPTER
GEMINI_API_KEY
LAW_OC
```

선택적 advanced:

```text
CODEX_TIMEOUT_MS
GCP_PROJECT_ID
PORT
SEARCH_DISPLAY
```

`CODEX_CLI_PATH`는 managed runtime이 canonical이므로 일반 사용자 설정으로 노출하지 않는다.

필요하면 developer/advanced override로만 유지하거나 UI에서 완전히 숨긴다.

### Secret safety

GET 응답에서 다음 실제 값을 반환하지 않는다.

```text
LAW_OC
GEMINI_API_KEY
auth token
```

표시는:

```text
설정됨
설정되지 않음
```

정도로 한다.

새 secret 입력은 write-only로 취급한다.

### Admin write safety

서버는 계속 `127.0.0.1`에만 bind한다.

Admin write:

```text
same-origin only
CORS disabled
JSON only
whitelist only
```

cross-origin write를 거부한다.

설정 저장은 가능하면 atomic write를 사용한다.

현재 startup-frozen config를 유지하고 저장 후:

```text
서버 재시작 후 적용됩니다.
```

라고 안내한다.

M10에서 hot reload configuration system을 새로 만들지 않는다.

## 18. Visual design 원칙

M10의 목적은 디자인 쇼케이스가 아니라 읽기 쉬운 법률 검색 제품이다.

우선순위:

```text
1. 판례 본문 가독성
2. 상태 구분
3. 정보 위계
4. 링크 식별성
5. 기존 화면 스타일 유지
6. 불필요한 시각효과 최소화
```

필수:

```text
기존 responsive layout 유지 가능
명확한 focus state
button disabled/loading state
충분한 line-height
긴 판결요지 white-space 처리
공식 링크 시각적 구분
error/notice/result 상태 구분
```

금지:

```text
과도한 animation
장식적 glassmorphism
법률 본문보다 강한 visual chrome
정보 의미와 무관한 색상 남용
```

## 19. Desktop / local PC QA

본 프로그램은 로컬 PC에서 서버를 직접 띄워 사용하는 제품이다. 모바일 전용 UI 구성과 모바일 viewport QA는 M10 필수 범위에서 제외한다.

이미 구현된 responsive CSS는 되돌리지 않고 유지할 수 있지만, release gate로 모바일 폭을 검증하지 않는다.

필수 확인 범위는 desktop 브라우저와 로컬 PC 운영 흐름이다.

```text
desktop
localhost 운영
검색 input/button
판례 카드와 법령 원문
admin form
```

## 20. Accessibility 최소 기준

최소:

```text

keyboard navigation
```

## 21. Renderer 구조

가능하면 backend renderer와 browser shell의 책임을 분리한다.

Backend:

```text
validated canonical result
→ result HTML / public result
```

Browser:

```text
검색 입력
progress
status
result container
```
