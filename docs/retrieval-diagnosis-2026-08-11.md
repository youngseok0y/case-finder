# 판례 회수·검증 진단

- 작성일: 2026-08-11
- 대상: Fable 규격 로컬 판례 검색기 `case-finder`
- 기준 브랜치: `main`
- 기준 체크포인트: `4844478` (`checkpoint: M5 golden verification before MCP upgrade`)
- 관련 명세: [`case-finder-spec.md`](../case-finder-spec.md)

## 요약

현재 실패의 1차 원인은 사건번호 검증보다 검색 후보 풀에 기대 판례가 들어오지 않는 회수 실패입니다. `korean-law-mcp` 4.9.6의 판례 검색은 기본적으로 제목검색을 수행하고, 제목검색 결과가 없을 때만 본문검색으로 폴백합니다. 판결문의 핵심 쟁점어가 사건명에 없으면 엉뚱한 제목 결과가 먼저 반환되어 본문 속 기대 판례가 후보 풀에 들어오지 않을 수 있습니다.

다만 결정론 검색 경로에는 이미 본문검색 강제 옵션이 반영되어 있습니다. 현재 남은 회수 취약점은 에이전틱 경로와 헌법재판소 도메인입니다. 헌법재판소 검색 핸들러는 본문검색 파라미터를 전달하지 않습니다.

## 실측·코드 근거

### 1. 제목검색 우선과 본문검색 폴백

설치된 `korean-law-mcp` 4.9.6의 `build/tools/precedent-search-core.js`에서:

- 첫 시도는 `args.search || 1`로 실행됩니다.
- `search === 2`일 때만 법제처 API에 `search=2`가 전달됩니다.
- 첫 시도에 결과가 있으면 본문검색 폴백까지 진행하지 않습니다.
- 본문검색 폴백은 첫 시도의 결과가 0건일 때만 선택됩니다.

따라서 제목에 쟁점어가 없는 판례는 제목검색 결과가 1건 이상인 순간 후보에서 누락될 수 있습니다. 사용자 재현 측정에서도 다음 현상이 확인되었습니다.

- `임금피크제`: 기대 사건이 제목검색 후보에 들어오지 않음
- 취업규칙 불이익변경 동의 관련 질의: 기대 사건 `2017다35588`이 후보 20건에 없음
- 본문검색 결과에서 기대 사건이 12/56위 또는 25/100위에 위치하는 사례 존재
- 헌재 도메인에서 `간통죄`, `양심적 병역거부` 검색이 0건이 되는 사례 존재

결정론 경로와 에이전틱 경로 모두 판례 도메인의 `search_decisions` 호출에 `options: { search: 2 }`를 전달합니다. 헌재·행정심판 도메인은 설치된 MCP 핸들러가 동일 옵션을 지원하지 않으므로 전달하지 않습니다.

헌재 핸들러도 설치된 4.9.6의 `build/tools/constitutional-decisions.js`에서 `query`, `caseNumber`, `display`, `page`, `sort`만 API 파라미터로 전달하며 `search=2`를 지원하지 않습니다.

### 2. 사건번호 병합 표기 불일치

검색 응답이 `2014두12598`로 반환되고 전문 응답이 `2014두12598, 12604`처럼 반환되는 경우 단순 문자열 비교는 실존 판례를 검증 실패로 처리합니다.

이 원인은 현재 `main` 기준으로 수정되었습니다. [`src/router.js`](../src/router.js)는 병합·축약 사건번호를 집합으로 전개하고 `caseNumberIncludes`/`caseNumberMatches`를 제공합니다. 예를 들어:

```text
2014두12598, 12604
→ 2014두12598
→ 2014두12604
```

구조적 비교 단위 테스트에서 단일 사건번호와 병합 전문의 일치가 확인되었습니다. 이 문제는 과거의 주요 원인이었지만 현재 자연어 실패의 유일한 원인으로 보기는 어렵습니다.

### 3. 노출 수와 후보 상한

현재 [`config.js`](../config.js)의 `searchDisplay`는 20입니다. 본문검색에서 정답이 25위에 있으면 `search=2`를 강제해도 후보 풀에 들어오지 않습니다. `candidateMax`는 별도로 20이므로 `searchDisplay`를 50으로 늘려도 Gemini에 전달되는 최종 후보 상한과 Gemini 호출 수는 그대로 유지됩니다.

에이전틱 경로는 검색 목록과 판례 상세를 구조화해 전달하므로, 검색 결과 뒤쪽의 provider ID가 문자 수 절단으로 사라지지 않습니다.

## 부차 요인 점검

1. 판시사항이 없는 하급심 후보는 현재 `previewMissingPenalty`로 보수적 감점을 적용합니다. 이는 실제 하급심 판별이 아니라 전문 미리보기 부재를 대리 지표로 사용하는 소프트 랭킹입니다.
2. `prompts/plan.txt`는 검색 표현을 요구하지만 법리 용어·2~3어 조합을 충분히 강제하지 않습니다. 실측상 일상어보다 `취업규칙 불이익변경 동의권 남용` 같은 법리어 조합이 유리하므로 프롬프트 보완 가치가 있습니다.
3. `admin_appeal`은 결정론 계획 스키마에는 반영되었지만 에이전틱 도메인 허용 집합에는 아직 없습니다.
4. `test/run.js`는 현재 병합 사건번호를 구조적으로 비교하며, `golden.json`의 대표 사건번호 기대값도 하나가 일치하면 통과하도록 수정되었습니다.
5. `searchRelatedLaws()`는 호출되지만 그 반환값은 현재 결과 구성에 사용되지 않습니다. 판례 회수의 직접 원인은 아니며, 불필요한 MCP 호출 비용과 계획상 법령 참조 누락을 만드는 문제입니다.

## 권장 적용 순서

### 1단계: MCP 의존성 변경 없이 실험

1. `searchDisplay`를 20에서 50으로 상향
2. 결정론 골든 세트를 `--include-natural --repeat=3`으로 재검증
3. 에이전틱 검색 결과를 구조화하고 raw 후보·선택·fallback 결과를 별도 기록
4. `searchDisplay` 50과 100의 회수율·응답시간을 비교

### 2단계: 계획·랭킹 보완

1. 검색계획 프롬프트를 법리 용어와 2~3어 조합 중심으로 보완
2. preview 부재 감점이 실제 하급심 후보를 줄이는지 별도 측정
3. `searchRelatedLaws()`를 제거하거나 실제 `lawReferences` 구성에 연결

### 3단계: 헌재와 MCP 업그레이드

현재 npm 조회 결과 `korean-law-mcp` 최신 버전은 프로젝트 고정 버전과 같은 4.9.6이므로 npm 버전 업그레이드는 불가능합니다. 헌재 본문검색 지원을 위해 GitHub 특정 커밋을 의존성으로 고정하는 방법은 가능하지만, 명세의 정확한 버전 고정·재현성 제약을 변경하므로 별도 승인 후 진행해야 합니다.

버전 변경을 승인하는 경우에는 명세 §17.2 절차에 따라 다음을 수행합니다.

1. 별도 브랜치 생성
2. 의존성은 한 항목만 변경
3. MCP 도구 목록·파라미터 스키마·핵심 응답 덤프 비교
4. 명세 §13 전체 재검증
5. 결과에 따라 명세와 변경 커밋을 함께 갱신
